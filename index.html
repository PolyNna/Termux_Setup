TERMUX — PHONE AS A LAPTOP
A Practical Guide to Building a Linux Desktop Environment on Android

Author: NNANNA POLYCARP

This book is written as a practical tutorial. Commands are presented for learning and personal experimentation. Android versions, Termux packages, Linux packages, device restrictions and available PRoot-Distro images can change over time. When a command depends on a current list or version, check the official source linked in the relevant section.

The goal is not to make your phone magically become a laptop. The goal is to build a useful Linux workspace on the phone, understand what each layer does, and know how to repair the setup when one layer fails.

How to use this book

1. Follow the order

Do not jump straight to the desktop. Each layer depends on the layer before it.

2. Read the prompt

$ means Termux. root@localhost:~# means you are inside Debian. >>> means Python.

3. Stop at checkpoints

Every major section tells you what success looks like before you continue.

FRONT MATTER 02
Introduction

Why Build a Laptop Environment on a Phone?

Sometimes you need a laptop and simply do not have access to it. That practical problem is enough to start looking for another route. An Android phone is already a powerful ARM computer; the challenge is giving it the tools, filesystem, display server and desktop environment needed for Linux work.

This tutorial teaches the route step by step. It does not assume that you already understand Linux. You will learn where commands are being run, why they are needed, what output is normal, what an error means, and where to return after fixing it.

Important idea
We are not replacing Android. Android remains the host operating system. Termux gives us a Linux-style command environment; PRoot-Distro gives us a rootless Linux userspace; Termux:X11 gives Linux graphical applications a way to draw on the Android screen.
ANDROID — the host
↓
TERMUX — terminal + Linux tools
↓
PRoot-Distro — Linux userspace
↓
DEBIAN — main Linux environment
↓
XFCE — desktop interface
↓
TERMUX:X11 — puts the GUI on the Android screen

Later we add Firefox, audio, LibreOffice, Python, Thonny and a startup shortcut. The most important troubleshooting event is the Android Process completed (signal 9) problem. It appears after the first graphical desktop is already visible, so the tutorial deliberately treats it at that exact point.

Chapter 1

Prepare Android and Install Termux

The first layer is the terminal. Do not install Debian or XFCE yet. First make Termux reliable.

1
Install Termux from an official source

For this tutorial, use the F-Droid build. Termux's official project provides the application and its source. Keep the installation source consistent; mixing incompatible Termux/plugin builds can cause problems.

Open Termux on F-Droid · Termux official GitHub

2
Open Termux and identify the prompt

When you see a prompt ending in $, you are in the Termux shell.

TERMUX 
$ pwd
What it does: pwd prints the current working directory. You are learning where the shell currently is before changing anything.
EXPECTED 
/data/data/com.termux/files/home
3
Allow Android storage access

This is optional for the core desktop, but useful when you want Termux to access Android shared storage.

TERMUX 
$ termux-setup-storage

Android should ask for storage permission. Approve it if you want the shared-storage links created.

4
Install the basic Termux tools
TERMUX 
$ pkg install x11-repo proot-distro git wget curl -y

pkg is Termux's package manager. x11-repo adds the X11 package repository. proot-distro will later install Debian. git, wget and curl are common download and project tools.

RETURN TO: the normal Termux $ prompt after installation finishes.
Battery setting
On Android, set Termux to Unrestricted battery/background usage if your phone provides that option. A Linux desktop is a long-running workload, and Android may otherwise suspend or kill background activity.

Chapter 2

Add Termux:X11 and Build the Linux Foundation

A terminal alone cannot display Linux desktop windows. Termux:X11 supplies the graphical bridge.

1
Install the Termux:X11 Android application

Termux:X11 has two pieces: an Android application and a companion Termux package. Android 8 or newer is required by the official project.

Open the official Termux:X11 nightly release · Official project

2
Install the Termux-side X11 package
TERMUX 
$ pkg install termux-x11-nightly -y

Wait for the package installation to finish. Do not open Debian yet.

3
Install Debian
TERMUX 
$ proot-distro install debian

PRoot-Distro creates a Linux userspace without requiring root access to Android. This is not the same as installing a second Android operating system.

TERMUX 
$ proot-distro login debian
DEBIAN 
root@localhost:~#
RETURN TO: if you see root@localhost:~#, Debian is open. You are no longer in the normal Termux shell.
4
Update Debian and install XFCE
DEBIAN 
root@localhost:~# apt update
DEBIAN 
root@localhost:~# apt install xfce4 xfce4-terminal dbus-x11 -y

xfce4 is the desktop environment. xfce4-terminal gives you a graphical terminal inside XFCE. dbus-x11 supplies tools used by desktop-session components.

Official PRoot-Distro reference
Read the official PRoot-Distro documentation . The current list of available distributions can change, so use proot-distro list when you need to check current aliases.

Chapter 3

Start X11, Launch XFCE and Test Firefox

This is the first moment when the phone begins to look like a Linux computer.

1
Start the X11 display server from Termux

First leave Debian if you are inside it.

DEBIAN → TERMUX 
root@localhost:~# exit

You should return to the Termux prompt ending in $.

TERMUX 
$ termux-x11 :1 &

The & puts the X11 server in the background so the shell remains usable.

2
Open the Termux:X11 Android app

Launch the installed Termux:X11 application. You may initially see a blank display. That is normal: the display server is running, but no Linux desktop has been started yet.

3
Enter Debian with shared temporary storage

Return to Termux. The official Termux:X11 guidance recommends --shared-tmp when using PRoot environments so the X11 socket can be shared correctly.

TERMUX 
$ proot-distro login debian --shared-tmp
RETURN TO: root@localhost:~#.
4
Tell Linux which display to use
DEBIAN 
root@localhost:~# export DISPLAY=:1

DISPLAY=:1 means graphical Linux programs should send their windows to display number 1.

DEBIAN 
root@localhost:~# xdpyinfo >/dev/null && echo "X11 CONNECTION OK"
EXPECTED 
X11 CONNECTION OK
5
Start the XFCE desktop

Now start the desktop session.

DEBIAN 
root@localhost:~# dbus-launch --exit-with-session startxfce4
What you should expect
XFCE should appear inside Termux:X11. You may see warnings in the terminal. Some of the warnings are known consequences of running a desktop designed for a normal Linux installation inside an Android/PRoot environment.

Important: this command normally stays attached to the graphical session. That means the prompt may not return while XFCE is running. Do not keep pressing keys expecting root@localhost:~# to come back.

6
Understand the warnings that appeared
KNOWN SESSION OUTPUT 
(xfce4-session:6805): xfce4-session-WARNING **: failed to run script: Failed to execute child process “/usr/bin/pm-is-supported” (No such file or directory)

** (xfdesktop:6908): WARNING **: Failed to get system bus: Could not connect: No such file or directory

The missing pm-is-supported warning is about a power-management helper that is not available in this environment. The system-bus warning is also common in a PRoot desktop where the full system services of a normal Linux installation are not present. These messages do not by themselves mean XFCE failed.

The important test is visual: does the XFCE desktop appear in Termux:X11?

7
Install Firefox as the first real GUI test

Do this after the desktop is visible. You may need another terminal session because the XFCE command is still attached to the running desktop. This is the one place in the early setup where opening a second Termux session is useful: it gives you a free shell while the first session is occupied by the desktop.

Why a second session?
It is not a second Linux desktop. It is simply another Termux shell. The first shell is busy keeping XFCE alive; the second shell gives you a prompt for the next command.

In the second Termux session:

SECOND TERMUX SESSION → DEBIAN 
$ proot-distro login debian --shared-tmp
DEBIAN 
root@localhost:~# apt install firefox-esr -y

Then launch it from that shell:

DEBIAN 
root@localhost:~# firefox-esr

If Firefox opens, you have proved that Linux GUI applications can run on the phone.

Checkpoint
Android → Termux → Termux:X11 → Debian → XFCE → Firefox. Stop here mentally. The desktop works, but the system has not yet been made stable against Android's phantom-process limit.

Chapter 4

The Desktop Appears — Then Signal 9 Happens

This chapter is deliberately placed after the first successful desktop. The problem is easier to understand when you have already seen the Linux desktop running.

The failure
Process completed (signal 9)

If Android terminates the Termux process tree, the desktop can suddenly disappear. The terminal may show that the process ended with signal 9. Signal 9 is SIGKILL: a process was forcibly killed rather than politely closing itself.

On Android 12 and later, phantom-process management can terminate child processes created by apps. A Linux desktop creates many child processes — XFCE components, DBus helpers, panels, browsers and other applications — so a desktop session can expose the restriction quickly. This behaviour has been documented in the Android/Termux ecosystem; the official-source links are collected in the appendix.

1
Do not treat the XFCE warnings as the signal-9 error

The earlier pm-is-supported and system-bus warnings are visible while XFCE is starting. Signal 9 is different: Android kills the running process tree. The two issues can appear in the same setup, but they are not the same problem.

2
Understand why the original terminal cannot continue

When you ran:

DEBIAN 
root@localhost:~# dbus-launch --exit-with-session startxfce4

that process became the foreground workload of the shell. While XFCE is alive, the shell is waiting for it. The fact that the desktop is visible is therefore expected to coincide with the absence of a normal prompt.

Do not do this
Do not assume the warning lines mean you should type the next command into the same occupied prompt. There is no normal prompt to receive it.
3
The practical route to the fix

At this exact stage, you need an independent Termux shell to run ADB. In the original workflow this meant opening another Termux session. That is not a workaround to hide; it is the correct consequence of having the XFCE process attached to the first shell.

Session A

Keep XFCE running. Do not kill it.

Session B

Use this free Termux shell for ADB and the Android-side fix.

What changes after the fix
Once the phantom-process limit has been changed and verified, you can close the extra shell and return to the normal startup flow. The desktop is then much less likely to disappear because of Android's phantom-process limit.

Chapter 5

Wireless ADB: Fix the Android Process Killer

ADB is Android Debug Bridge. Here it is used to change the Android configuration responsible for the phantom-process limit.

1
Prepare the Android developer tools

Open Android Settings and enable Developer Options if they are not already enabled. Then open Developer Options and enable Wireless debugging. Android will display the information needed for pairing and connecting.

Do not copy a sample IP address, port or pairing code from a tutorial. Use the values shown by your own phone.

2
Repair the Termux ADB installation if necessary

If your Termux ADB command produced this error:

ERROR 
CANNOT LINK EXECUTABLE "adb": cannot locate symbol "_ZNSt6__ndk113__hash_memoryEPKvm"

first check which package owns the executable:

TERMUX 
$ dpkg -S $PREFIX/bin/adb

If the result identifies the android-tools package, reinstall it:

TERMUX 
$ pkg reinstall android-tools

A message about the ADB daemon not being connected yet is different from a broken executable. For example:

DAEMON MESSAGE 
cannot connect to daemon at tcp:5037: Connection refused

That means ADB itself can be invoked but has not established its daemon connection.

3
Pair ADB over Wireless Debugging

Use the pairing address and pairing port displayed by Android.

TERMUX 
$ adb pair IP_ADDRESS:PAIRING_PORT

Android will ask for the pairing code shown on the Wireless Debugging screen. Enter that code exactly.

Then connect using the separate IP address and connection port shown under the active debugging connection:

TERMUX 
$ adb connect IP_ADDRESS:PORT
TERMUX 
$ adb devices

You want to see the phone listed as a connected device.

If you see “protocol fault”
A pairing attempt may fail with a message such as protocol fault (couldn't read status message): Success. Treat this as a connection/pairing hiccup first: check that Wireless debugging is still enabled, verify the displayed ports, and retry the pairing/connection process rather than changing unrelated Linux settings.
4
Apply the phantom-process configuration

Run these from the free Termux session — not inside the busy XFCE session.

ADB — COMMAND 1 
adb shell "/system/bin/device_config set_sync_disabled_for_tests persistent"

This makes the relevant DeviceConfig settings persistent for testing/configuration rather than being immediately re-synchronized away.

ADB — COMMAND 2 
adb shell "/system/bin/device_config put activity_manager max_phantom_processes 2147483647"

This sets the Android Activity Manager phantom-process limit to a very large value.

VERIFY 
adb shell "/system/bin/device_config get activity_manager max_phantom_processes"
EXPECTED 
2147483647
Why the number is so large
The purpose is to move the phantom-process ceiling far beyond the number of child processes a normal Termux desktop session is expected to create. The exact behaviour can vary by Android/OEM version, so treat the verification command as the important checkpoint.
5
Return to the desktop

Once the setting verifies, return to the Termux:X11 desktop. If the old session has already been killed, restart it from the beginning of the X11/Debian launch sequence. If it is still alive, continue using it.

RETURN TO: the normal Linux startup path: Termux → X11 → Debian → XFCE. You no longer need the temporary ADB shell for normal desktop use.
Stable-desktop checkpoint
The critical early build is now complete. Android is hosting Termux; Termux is hosting Debian through PRoot; Termux:X11 displays XFCE; and the Android phantom-process limit has been addressed. From here, the remaining chapters add capabilities rather than rescuing the core desktop.

Chapter 6

Make the Desktop Useful: Audio and LibreOffice

A desktop that only displays windows is not enough. The next two upgrades make it practical for browsing, documents and spreadsheets.

Part A — Audio through PulseAudio

1
Install PulseAudio in Termux
TERMUX 
$ pkg install pulseaudio -y
2
Configure the Android audio sink
TERMUX 
$ sed -i 's/module-sles-sink/module-aaudio-sink/g' $PREFIX/etc/pulse/default.pa

This replaces the older sink module name with the AAudio sink used in the tested setup.

3
Start PulseAudio and expose its local TCP protocol
TERMUX 
$ pulseaudio --start --load="module-native-protocol-tcp auth-ip-acl=127.0.0.1 auth-anonymous=1" --exit-idle-time=-1
TERMUX 
$ pactl load-module module-native-protocol-tcp auth-ip-acl=127.0.0.1 auth-anonymous=1

The returned number, such as 18, is a module ID. It is not an error.

VERIFY 
$ pactl info | grep -E "Server Name|Default Sink"
EXPECTED 
Server Name: pulseaudio
Default Sink: AAudio_sink
4
Tell Debian to use the local PulseAudio server
DEBIAN 
root@localhost:~# export PULSE_SERVER=127.0.0.1

127.0.0.1 means the same phone. Debian sends audio to the PulseAudio service running in Termux on that phone.

No sound?
Check PulseAudio in Termux first with pactl info. Then make sure PULSE_SERVER=127.0.0.1 is set inside Debian before launching the application. Restart the affected application after changing the variable.

Part B — LibreOffice

1
Install LibreOffice
DEBIAN 
root@localhost:~# apt update
DEBIAN 
root@localhost:~# apt install libreoffice -y

Delayed-item warnings can appear during a large package installation. What matters is whether the installation ultimately completes.

VERIFY 
root@localhost:~# dpkg --audit

No output from dpkg --audit is a good sign that there are no packages currently reported as needing repair.

VERIFY 
root@localhost:~# libreoffice --version
TESTED RESULT 
LibreOffice 25.2.3.2 520(Build:2)
Checkpoint
You now have a graphical Linux desktop that can browse with Firefox, play audio through the phone, and run a full office suite including Calc for spreadsheet work.

Chapter 7

Python, Virtual Environments and Thonny

This is where the phone becomes useful for programming and data work, not just graphical browsing.

1
Check Debian's Python
DEBIAN 
root@localhost:~# python3 --version
TESTED 
Python 3.13.5

Start Python if you want to confirm it works:

DEBIAN 
root@localhost:~# python3
PYTHON 
>>> print("Hello, Polycarp!")
Hello, Polycarp!
>>> exit()

exit() leaves Python and returns you to the Debian prompt.

2
Avoid mixing Termux Python with Debian Python

A subtle but important problem appeared during the setup: pip3 could point to the Termux Python installation even while you were thinking about Debian Python.

CHECK 
root@localhost:~# pip3 --version
EXAMPLE OF THE WRONG CONTEXT 
pip 26.2.1 from /data/data/com.termux/files/usr/lib/python3.14/site-packages/pip (python 3.14)

The path shows that this is Termux's pip. For Debian Python, use the interpreter itself to invoke pip:

DEBIAN 
root@localhost:~# python3 -m pip --version
TESTED 
pip 25.1.1 from /usr/lib/python3/dist-packages/pip (python 3.13)
Rule
Inside Debian, prefer python3 -m pip. It makes the Python interpreter you intend to use explicit.
3
Create a virtual environment
DEBIAN 
root@localhost:~# apt install python3-venv -y
DEBIAN 
root@localhost:~# python3 -m venv ~/data
DEBIAN 
root@localhost:~# source ~/data/bin/activate

Your prompt should now begin with (data). That label means the virtual environment is active.

4
Install common data packages
DATA ENVIRONMENT 
(data) root@localhost:~# python3 -m pip install numpy pandas matplotlib

In the tested setup this installed NumPy 2.5.3, pandas 3.0.6 and Matplotlib 3.11.2. Package versions can change; the important lesson is to install them inside the environment you intend to use.

5
Install Thonny
DEBIAN 
root@localhost:~# apt install thonny -y

Thonny 4.1.7-1 was tested. A SyntaxWarning concerning an invalid escape sequence in an autocomplete plugin file appeared during installation/use; that warning was not a failure. In Thonny, the tested interpreter selection was Local Python 3 with executable /usr/bin/python3.

Chapter 8

One-Tap Startup with Termux:Widget

Once the desktop works, repeating a long startup sequence every time is unnecessary. We can put the startup commands into one script and expose that script as an Android home-screen shortcut.

1
Install Termux:Widget

Open Termux:Widget on F-Droid . The plugin can expose executable scripts placed in $HOME/.shortcuts/.

2
Create the startup script

In Termux, create the file:

TERMUX 
$ nano ~/start-linux.sh

Paste the following script into the editor:

START-LINUX.SH 
#!/data/data/com.termux/files/usr/bin/bash

termux-wake-lock

# Start Termux:X11 if it is not already running
if [ ! -S "$TMPDIR/.X11-unix/X1" ] && [ ! -S "/tmp/.X11-unix/X1" ]; then
    termux-x11 :1 &
    sleep 3
fi

# Start PulseAudio if it is not already running
pulseaudio --start --load="module-native-protocol-tcp auth-ip-acl=127.0.0.1 auth-anonymous=1" --exit-idle-time=-1

# Make the PulseAudio TCP connection available
pactl load-module module-native-protocol-tcp auth-ip-acl=127.0.0.1 auth-anonymous=1 2>/dev/null

# Start XFCE
proot-distro login debian --shared-tmp -- bash -c \
'export DISPLAY=:1; export PULSE_SERVER=127.0.0.1; dbus-launch --exit-with-session startxfce4' &

Save the file and leave the editor.

3
Make the script executable
TERMUX 
$ chmod +x ~/start-linux.sh
VERIFY 
$ ls -l ~/start-linux.sh

The permissions should show executable bits, for example -rwx------.

4
Test the script before adding a shortcut
TERMUX 
$ ~/start-linux.sh

Android may ask whether Termux should be allowed to keep running in the background. Allow it if you want the desktop to remain active. You may also see a message that the wake lock is held.

Because the script backgrounds the desktop launch, the Termux shell can remain usable. This is different from manually running the foreground XFCE command in Chapter 3.

5
Add it to Termux:Widget
TERMUX 
$ mkdir -p ~/.shortcuts
TERMUX 
$ cp ~/start-linux.sh ~/.shortcuts/"Start Linux"
TERMUX 
$ chmod +x ~/.shortcuts/"Start Linux"

Use the Termux:Widget Android home-screen control to add the Start Linux shortcut. Tapping it should execute the script.

Reliability boundary
This shortcut was tested after the desktop had been stabilized. It worked when Termux remained available. Do not assume that a widget can revive every component after Android has completely killed all required processes. If everything has been killed, open Termux and Termux:X11 again before using the shortcut.

Chapter 9

Ubuntu, Storage and Android APIs

The main desktop in this tutorial is Debian. Ubuntu is included as an optional separate environment, while storage and Android API sections explain the boundaries between Linux and Android.

Part A — Optional Ubuntu

1
Check which PRoot-Distro images are currently available
TERMUX 
$ proot-distro list

Do this instead of blindly assuming an alias will always exist. PRoot-Distro's available distributions can change.

2
Install and enter Ubuntu if the current list provides it
TERMUX 
$ proot-distro install ubuntu
TERMUX 
$ proot-distro login ubuntu

Ubuntu is a separate userspace. Packages installed in Ubuntu do not automatically appear in Debian.

Scope
This tutorial includes Ubuntu as an optional environment. The original tested desktop build is Debian + XFCE; do not confuse the optional Ubuntu environment with the tested Debian desktop.

Part B — Android shared storage

Termux and Debian do not automatically share every Android directory as if they were one normal Linux filesystem. termux-setup-storage creates Termux-side links after Android grants permission. When you need a file from Android storage inside Linux, understand which filesystem you are currently inside before assuming a path exists.

Part C — Termux:API and the camera lesson

Install the Android add-on and the Termux-side package from the official sources when you need Android API access.

Termux:API on F-Droid · Termux:API official GitHub

1
Install the Termux-side API package
TERMUX 
$ pkg install termux-api -y
TERMUX 
$ command -v termux-camera-photo

This confirms whether the camera command exists in Termux.

Camera ≠ Linux webcam

Termux:API exposes Android functions to Termux. That does not automatically create a Linux video device such as /dev/video0 that Firefox or another Linux application can treat as a webcam.

In the tested setup, the camera command did not become a working Linux webcam bridge. A true webcam workflow would require an additional Android-to-Linux video bridge or network camera solution.

Chapter 10

Recovery, Limits and the Finished System

A good setup is not one that never produces warnings. A good setup is one where you know which warnings matter, which do not, and where to return when something breaks.

Recovery map

Symptom First thing to check Where to return
Signal 9 Android phantom-process configuration and Wireless ADB verification. Termux free shell / ADB stage.
Cannot open display Is Termux:X11 running? Is DISPLAY=:1 set? Was Debian entered with --shared-tmp? Termux → X11 → Debian.
XFCE shows warnings Check whether the desktop actually appears. The pm-is-supported and system-bus messages can be environmental warnings. XFCE startup stage.
No audio Check PulseAudio with pactl info; set PULSE_SERVER=127.0.0.1 in Debian. Audio stage.
Python package installs into the wrong place Check python3 -m pip --version and the path. Avoid blindly using a pip3 command that points to Termux. Python environment stage.
Widget does nothing Check ~/.shortcuts/ and executable permission. Startup script stage.

Chromium and the root warning

Do not make --no-sandbox your default fix
A Chromium-based browser may warn that running as root without --no-sandbox is unsupported. Do not casually turn off browser sandboxing just to remove the warning. A safer long-term design is to run browsing under a normal Linux user where practical. Firefox ESR was the tested GUI browser in this setup.

The complete architecture

ANDROID
↓
TERMUX + BATTERY/BACKGROUND ACCESS + WAKE LOCK
↓
TERMUX:X11 + PULSEAUDIO
↓
PRoot-Distro → DEBIAN
↓
XFCE → FIREFOX → LIBREOFFICE → PYTHON → THONNY
↓
TERMUX:WIDGET → ONE-TAP STARTUP
The important achievement is not simply seeing a desktop on the phone. It is understanding the layers well enough that, when the desktop disappears, you know which layer to inspect first.
Final checkpoint
If you can explain what Termux, PRoot-Distro, Debian, XFCE, Termux:X11, PulseAudio and ADB each do — and you know why the signal-9 fix had to be performed from a separate free shell — you understand the architecture rather than merely memorizing commands.

Glossary

Android host

The operating system that remains in control of the phone and its hardware.

Termux

An Android application that provides a terminal and a large collection of Linux-style command-line tools.

PRoot-Distro

A Termux tool for installing and entering rootless Linux userspaces.

Debian

The main Linux distribution used in this tutorial.

XFCE

The graphical desktop environment used to provide windows, panels, menus and a file manager.

X11

The display system used here so Linux GUI applications can draw through Termux:X11.

PulseAudio

The audio server used to route Linux application sound to the Android-side audio sink.

ADB

Android Debug Bridge, used here through Wireless Debugging to change an Android process-management setting.

One last habit
When troubleshooting, do not restart everything blindly. Identify the layer that failed, verify it, fix it, and then return to the checkpoint immediately before the failure.
