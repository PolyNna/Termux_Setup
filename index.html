About This Book

I did not write this book as a collection of commands copied from somewhere else. I wrote it from the process I actually went through while trying to turn my Android phone into something much closer to a Linux computer.

That difference matters.

When something worked, I recorded what I did. When something failed, I recorded the failure. When I found a fix, I recorded the fix at the point where it became necessary.

“If you know where you are, what you are doing and what you should see next, Termux becomes much easier to understand.”

The purpose of this book is therefore not simply to tell you what command to type. It is to help you understand what is happening around that command.

Important

Commands and package versions can change over time. Always check current official documentation when a package, Android version or repository behaves differently from the examples in this book.

Before We Begin

What Termux actually is, what we are building, what Android allows us to do, and the mental model that makes the rest of the book easier.

1. Before We Begin

Before installing anything, I want to make one thing clear: Termux is not simply another Android terminal emulator. It gives Android a Linux-like command-line environment where I can install packages and run many familiar Linux tools.

The desktop we eventually see is also not a normal Windows or macOS desktop magically installed inside Android. It is a Linux userspace running through Android, with an X11 display server providing the graphical interface.

The prompts matter

Prompt Where I am
$ Normal Termux shell
root@localhost:~# Inside the Debian PRoot environment
>>> Inside Python

Do not ignore the prompt

A large part of the confusion in Linux-on-Android setups comes from running the correct command in the wrong environment.

Preparing Termux

I first installed Termux from F-Droid rather than relying on an unrelated APK source.

Official Termux — F-Droid Termux — Official GitHub

After installation, I opened Termux and updated the package information.

TERMUX
$ pkg update $ pkg upgrade -y

The first command refreshes package information. The second upgrades installed packages.

Background activity

Because I wanted the Linux desktop to remain alive for longer sessions, I also had to pay attention to Android's battery management.

Important Android setting

Set Termux to allow unrestricted battery/background activity where the device provides that option.

I also used:

$ termux-wake-lock

This helps prevent the phone from aggressively sleeping the Termux process during long-running work.

Installing Termux and Termux:X11

This is where the phone begins moving from a normal Android device toward the Linux desktop environment I wanted.

Installing the X11 Components

I installed the repositories and tools required for the rest of the setup.

TERMUX
$ pkg install x11-repo proot-distro git wget curl -y Installing required packages... Done. $ pkg install termux-x11-nightly -y

What each part means

Package Purpose
x11-repo Provides X11-related packages
proot-distro Manages Linux distributions in Termux
git Version-control tool
wget Command-line downloader
curl Command-line network utility
Official Termux:X11 GitHub Termux:X11 Nightly Releases

Starting X11

Termux:X11 is the graphical display side of the setup. Installing it is not the same thing as starting it.

$ termux-x11 :1 &

The :1 identifies the X display we are going to use.

If X11 becomes stuck or needs to be restarted, I used:

$ pkill -f termux-x11 $ termux-x11 :1 &

Why restart X11?

A graphical session can remain in a bad state even though Termux itself is still running. Restarting the X11 server gives the desktop a clean display target.

CHAPTER THREE

Debian, XFCE and the Linux Desktop

The point where the command line becomes a graphical Linux desktop.

Installing Debian

I used PRoot-Distro to install Debian.

$ proot-distro install debian $ proot-distro login debian
CHECKPOINT — WHERE AM I?

At this point I should see something similar to:

root@localhost:~#

That means I am inside Debian, not normal Termux.

Install XFCE

root@localhost:~# apt update root@localhost:~# apt install xfce4 xfce4-terminal dbus-x11 -y

XFCE provides the graphical desktop environment. DBus helps desktop applications communicate with one another.

Connecting Debian to X11

I exited and re-entered Debian with the shared temporary directory because Termux:X11 and the PRoot environment need to be able to see the same X11 socket.

$ proot-distro login debian --shared-tmp root@localhost:~# export DISPLAY=:1 root@localhost:~# xdpyinfo >/dev/null && echo "X11 CONNECTION OK" X11 CONNECTION OK

That last line was an important checkpoint for me. It confirmed that Debian could communicate with the X11 display.

Starting XFCE

root@localhost:~# dbus-launch --exit-with-session startxfce4

What success looks like

The XFCE desktop appears with items such as the Applications menu, desktop icons, panels, a clock and a mouse pointer.

CHAPTER FOUR

Firefox and the Signal 9 Problem

Firefox became my first serious graphical application test. Then Android showed me a problem that had nothing to do with Firefox itself.

Firefox: My First GUI Test

Once the XFCE desktop appeared, I wanted a real application rather than simply looking at the desktop.

I installed Firefox ESR from Debian.

root@localhost:~# apt install firefox-esr -y root@localhost:~# firefox-esr

Firefox ESR became my first major confirmation that the graphical environment was doing something useful.

FIRST MAJOR DESKTOP CHECKPOINT

Android → Termux → Debian → X11 → XFCE → Firefox.

At this stage I had something that genuinely looked and behaved like a Linux desktop running on my Android phone.

The Problem: Signal 9

THE ERROR I ACTUALLY ENCOUNTERED

Process completed (signal 9)

The desktop or its processes could suddenly disappear.

At first, it would be easy to assume that Debian, XFCE or Firefox was broken. That was not the real issue.

Android has process-management mechanisms that can terminate phantom or cached processes. In this setup, that could kill Linux desktop processes.

This was one of the most important lessons of the entire project: sometimes the Linux environment is working, but Android decides that the process should not continue.

The fix

I used Android Wireless Debugging and ADB to change the relevant process-management configuration.

adb shell "/system/bin/device_config set_sync_disabled_for_tests persistent" adb shell "/system/bin/device_config put activity_manager max_phantom_processes 2147483647"

Verification

adb shell "/system/bin/device_config get activity_manager max_phantom_processes" 2147483647

Stable desktop checkpoint

After this fix I was able to continue using the desktop without the earlier repeated signal 9 crashing problem. This became the stable foundation for the later audio, LibreOffice, Python and automation work.

CHAPTER FIVE

ADB and Wireless Debugging

The tool that allowed Android itself to become part of the troubleshooting process.

My ADB Problem

ADB did not immediately work perfectly in Termux. One of the errors I encountered was:

ADB LINKER ERROR

CANNOT LINK EXECUTABLE "adb": cannot locate symbol "_ZNSt6__ndk113__hash_memoryEPKvm"

Before guessing, I checked which package owned the executable.

$ dpkg -S /data/data/com.termux/files/usr/bin/adb android-tools: /data/data/com.termux/files/usr/bin/adb

The executable belonged to the Android tools package, so I reinstalled that package.

$ pkg reinstall android-tools

I then encountered another daemon-related message:

cannot connect to daemon at tcp:5037: Connection refused

This was a connection/daemon problem rather than proof that ADB itself could never work.

Wireless Debugging

On the Android phone I enabled:

  • Developer Options
  • Wireless Debugging

Android displays the actual IP address, pairing port, connection port and pairing code. I used the values shown by the phone rather than inventing them.

$ adb pair IP_ADDRESS:PAIRING_PORT $ adb connect IP_ADDRESS:PORT $ adb devices

Do not copy example addresses

Replace the placeholders with the values displayed by your own Android device.

During pairing I also encountered:

protocol fault (couldn't read status message): Success

I treated this as a pairing/connection hiccup. I checked Wireless Debugging again, retried the pairing and then verified the device with adb devices.

CHAPTER SIX

Audio and PulseAudio

A desktop is much more useful when the applications can use the phone's speaker.

Installing PulseAudio

After the desktop was stable, I moved on to audio.

$ pkg install pulseaudio -y

I adjusted the PulseAudio configuration:

$ sed -i 's/module-sles-sink/module-aaudio-sink/g' $PREFIX/etc/pulse/default.pa

Then I started PulseAudio with a local TCP connection:

$ pulseaudio --start --load="module-native-protocol-tcp auth-ip-acl=127.0.0.1 auth-anonymous=1" --exit-idle-time=-1 $ pactl load-module module-native-protocol-tcp auth-ip-acl=127.0.0.1 auth-anonymous=1 18

The number 18 was a module ID returned by PulseAudio. It was not an error.

Checking the Audio Server

$ pactl info | grep -E "Server Name|Default Sink" Server Name: pulseaudio Default Sink: AAudio_sink

Inside Debian I used:

root@localhost:~# export PULSE_SERVER=127.0.0.1

The address 127.0.0.1 means the local machine — in this case, the same Android phone.

AUDIO CHECKPOINT

Firefox was launched with the PulseAudio environment available, and YouTube audio played through the phone's speaker.

CHAPTER EIGHT

Python, pip, venv and Thonny

Once the desktop could run normal applications, I started turning it into a development and data-analysis environment.

Python

root@localhost:~# python3 --version Python 3.13.5 root@localhost:~# python3 >>> print("Hello, Polycarp!") Hello, Polycarp! >>> exit() root@localhost:~#

The pip confusion

This was an important environment lesson. Running pip3 gave me Termux's Python installation:

root@localhost:~# pip3 --version pip 26.2.1 from /data/data/com.termux/files/usr/lib/python3.14/site-packages/pip (python 3.14)

That was not the Debian Python environment I was trying to use.

The safer approach inside Debian was:

root@localhost:~# python3 -m pip --version pip 25.1.1 from /usr/lib/python3/dist-packages/pip (python 3.13)

My rule

Inside Debian, I use python3 -m pip when I want to make absolutely sure pip belongs to the Python interpreter I am using.

Virtual Environment

root@localhost:~# apt install python3-venv -y root@localhost:~# python3 -m venv ~/data root@localhost:~# source ~/data/bin/activate (data) root@localhost:~#

The (data) appearing before the prompt means that the virtual environment is active.

Data packages

(data) root@localhost:~# python3 -m pip install numpy pandas matplotlib NumPy 2.5.3 pandas 3.0.6 Matplotlib 3.11.2

Thonny

root@localhost:~# apt install thonny -y Thonny 4.1.7-1

Thonny produced a SyntaxWarning involving an invalid escape sequence in one of its Python files. It was a warning, not an installation failure.

CHAPTER NINE

Automation, Termux:Widget and Android APIs

At this point the phone was no longer just running Linux. I started making the whole environment easier to start and interact with.

My Startup Script

Instead of manually starting every component, I created:

root@localhost:~# nano ~/start-linux.sh

The final script was:

#!/data/data/com.termux/files/usr/bin/bash termux-wake-lock if [ ! -S "$TMPDIR/.X11-unix/X1" ] && [ ! -S "/tmp/.X11-unix/X1" ]; then termux-x11 :1 & sleep 3 fi pulseaudio --start \ --load="module-native-protocol-tcp auth-ip-acl=127.0.0.1 auth-anonymous=1" \ --exit-idle-time=-1 pactl load-module module-native-protocol-tcp \ auth-ip-acl=127.0.0.1 auth-anonymous=1 2>/dev/null proot-distro login debian --shared-tmp -- bash -c \ 'export DISPLAY=:1; export PULSE_SERVER=127.0.0.1; \ dbus-launch --exit-with-session startxfce4' &

I then made it executable:

$ chmod +x ~/start-linux.sh $ ls -l ~/start-linux.sh -rwx------ ... start-linux.sh

Termux:Widget

I installed Termux:Widget and placed the startup script in its shortcuts directory.

Official Termux:Widget — F-Droid
$ mkdir -p ~/.shortcuts $ cp ~/start-linux.sh ~/.shortcuts/"Start Linux" $ chmod +x ~/.shortcuts/"Start Linux"

I then added the Termux:Widget shortcut to the Android home screen.

AUTOMATION CHECKPOINT

I logged out of the desktop, exited Termux:X11 while keeping Termux available, tapped Start Linux, opened Termux:X11 and XFCE appeared again.

Important limitation

I did not treat this as proof of cold-start reliability when both Termux and Termux:X11 had been completely killed.

Termux:API and the Camera

I installed Termux:API and confirmed that the camera command existed:

$ command -v termux-camera-photo /data/data/com.termux/files/usr/bin/termux-camera-photo
Official Termux:API — F-Droid Termux:API — Official GitHub

Android camera ≠ Linux webcam

This is one of the most important distinctions in this book. Termux:API gives Termux access to Android camera functionality. It does not automatically create a Linux webcam device such as /dev/video0.

I did not claim that I had successfully turned the phone's camera into a Linux browser webcam because I had not.

CHAPTER TEN

Ubuntu, Recovery and Going Further

Debian was the environment I actually built and tested. Ubuntu is another option available through PRoot-Distro.

Ubuntu

I did not want Ubuntu to be presented as though it were another name for Debian. They are separate Linux environments.

First I check what distributions are currently available:

$ proot-distro list

If the current list contains Ubuntu, it can be installed with the corresponding current alias:

$ proot-distro install ubuntu $ proot-distro login ubuntu

Why check the list first?

Distribution aliases and availability can change. I do not want a book to make readers blindly type an old alias.

Debian or Ubuntu?

Installing Ubuntu does not remove Debian. Each PRoot-Distro environment has its own filesystem and packages.

Storage

Android storage and Linux filesystem paths are not exactly the same thing.

To give Termux access to shared Android storage:

$ termux-setup-storage

Android then asks for storage permission.

Chromium and the root warning

WARNING ENCOUNTERED

Running as root without --no-sandbox is not supported

I do not recommend casually solving this by disabling browser sandboxing. A safer approach is to use a normal non-root desktop user where practical, or use the Firefox ESR setup that was already tested in this environment.

Recovery Guide

When something breaks, I do not immediately reinstall everything. I work backwards from the layer that failed.

Symptom First thing to check
Signal 9 Android phantom-process management / ADB configuration
Cannot open display Termux:X11 and DISPLAY=:1
XFCE does not appear DBus, X11 and shared temporary directory
No browser sound PulseAudio and PULSE_SERVER
Wrong pip version python3 -m pip
ADB linker error Reinstall android-tools
Camera command exists but webcam unavailable Android API is not a Linux V4L2 webcam

The rule that saved me time

Fix the layer that failed. Do not reinstall the whole system because one component has a problem.

Glossary

ADB

Android Debug Bridge. A tool that allows commands to be sent to an Android device.

DBus

A communication system used by Linux desktop applications and services.

Display

The X11 graphical destination used by GUI applications.

PRoot

A userspace mechanism that allows a Linux filesystem and environment to operate without traditional root access.

XFCE

A lightweight Linux desktop environment.

PulseAudio

A sound server used to provide audio services to applications.

Virtual Environment

An isolated Python environment where packages can be installed separately from the system Python environment.

Termux:X11

The X11 display component used to show Linux graphical applications on Android.
