Foreword

This book began with a practical problem.

There were things I needed to do that I would normally use a laptop for, but my laptop was not available.

Instead of simply waiting for the laptop to become available again, I started looking for alternatives.

That led to a simple question:

Can an Android phone handle some of the work I normally do on a laptop?

Not everything. Not perfectly. But perhaps enough to be useful.

The answer required more than installing one application. It required understanding how Android, Termux, Linux distributions, graphical desktops and Android's own process management could work together.

This book therefore teaches the process from the beginning.

It does not assume that you already understand Linux. When a command appears, the book explains where to type it, what the command means, what should happen, and what to check when the expected result does not appear.

The goal is not simply to make the setup work once. The goal is to understand what you are building.

Chapter 01

The Idea: Why Build Linux on a Phone?

Before installing anything, understand what we are trying to build and what the finished system can and cannot do.

The problem comes first

A laptop is useful because it gives us a large screen, a keyboard, desktop applications, a filesystem and the freedom to install development tools.

But there are situations where the laptop is unavailable.

In that situation, an Android phone may already have enough hardware to perform some of the work, but Android does not normally present itself like a Linux desktop computer.

This project explores what happens when we add the missing pieces.

What are we building?

Android
↓
Termux
↓
PRoot-Distro
↓
Debian
↓
XFCE
↓
Termux:X11
↓
Linux Desktop

Important: Linux is not replacing Android

Android remains the operating system underneath the whole setup.

Termux provides a Linux-like user environment. PRoot-Distro provides isolated Linux environments such as Debian. XFCE provides the desktop interface. Termux:X11 provides the graphical display connection.

Learning checkpoint

If you understand that we are building Linux inside Android rather than replacing Android, you are ready to begin.

Chapter 02

Preparing Android and Installing Termux

We begin with the foundation. Do not rush into Debian yet.

2.1 Install Termux

Install Termux from a trusted source. The F-Droid distribution is one established source for the application.

Official source: Termux on F-Droid

WHERE ARE WE?
Android Settings / F-Droid → Termux.

After installation, open Termux.

You should see a shell prompt
$

That dollar sign means we are currently working in Termux.

2.2 Update Termux

Step 1

First refresh the package information.

Termux command 
pkg update
What does this mean?

pkg is Termux's package manager. update refreshes information about packages available to Termux.

Step 2

Now upgrade installed packages where updates are available.

Termux command 
pkg upgrade
Why do this?

We want the Termux environment to be reasonably up to date before installing the rest of the components.

2.3 Install the basic tools

We need several packages before we can build the Linux environment.

Termux command 
pkg install x11-repo proot-distro git wget curl -y

x11-repo — provides access to X11-related packages.

proot-distro — manages Linux distribution environments.

git — version-control software used by many development projects.

wget — command-line downloading tool.

curl — command-line network/data-transfer tool.

-y — automatically answers yes to the installation confirmation.

CHECKPOINT
  • Termux is installed.
  • Termux packages are updated.
  • PRoot-Distro is installed.
  • The X11 repository is available.

2.4 Install Termux:X11

Termux:X11 consists of an Android application and a Termux-side package.

Official project: Termux:X11 on GitHub

Install the Android application first.

Then return to Termux.

Termux command 
pkg install termux-x11-nightly -y

This installs the Termux-side component that works with the Termux:X11 Android application.

2.5 Give Termux enough freedom to run

Android can restrict background activity to save battery. A Linux desktop can have many processes running simultaneously.

Open Android Settings and look for the battery/background settings for Termux.

If your device provides an Unrestricted battery option, select it for Termux. Apply the appropriate setting to Termux:X11 as well if available.

2.6 Hold a wake lock

Termux command 
termux-wake-lock

This requests a wake lock so the device does not simply go to sleep while Termux is expected to continue doing work.

Checkpoint

Do not continue until Termux:X11 is installed and Termux itself opens normally.

Chapter 03

Termux:X11, Debian and XFCE

Now we create the Linux environment that will eventually become our desktop.

3.1 Check available distributions

WHERE ARE WE?
Termux. You should see $.
Termux command 
proot-distro list

This displays the Linux distributions available through the installed version of PRoot-Distro.

Why check first?

Distribution aliases can change between software versions. Checking the current list prevents us from assuming that a particular alias must exist.

3.2 Install Debian

Termux command 
proot-distro install debian

PRoot-Distro downloads and creates a Debian filesystem that can be entered from Termux.

It does not replace Android.

It does not turn the phone into a dual-boot computer.

It gives us a separate Linux userspace inside Termux.

3.3 Enter Debian

Termux command 
proot-distro login debian

This enters the Debian environment.

Your prompt changes
root@localhost:~#
IMPORTANT:

We are now inside Debian. Commands intended for Termux should not automatically be typed here.

3.4 Install XFCE

Debian command 
apt update

apt is Debian's package manager. update refreshes Debian's package information.

Debian command 
apt install xfce4 xfce4-terminal dbus-x11 -y

xfce4 — the desktop environment.

xfce4-terminal — terminal application for XFCE.

dbus-x11 — DBus support used by graphical sessions.

-y — automatically confirms installation prompts.

Checkpoint

  • Debian installed.
  • Debian opens with root@localhost:~#.
  • XFCE is installed.
  • Termux:X11 is installed.

We are now ready to connect the Linux desktop to the phone's graphical display.

Chapter 04

Making the Linux Desktop Appear

This is where the pieces finally connect.

4.1 Leave Debian temporarily

WHERE ARE WE?
We need to return to Termux before starting Termux:X11.
Debian command 
exit

exit leaves the current shell. Here it takes us from Debian back to Termux.

4.2 Start Termux:X11

Termux command 
termux-x11 :1 &

termux-x11 starts the X11 server.

:1 identifies the display number.

& allows the command to run in the background.

Now open the Termux:X11 Android application.

4.3 Enter Debian with shared temporary storage

Termux command 
proot-distro login debian --shared-tmp

--shared-tmp allows the PRoot environment to share the temporary directory with the Termux environment.

This is important for applications that need to communicate through temporary sockets, including the X11 connection.

4.4 Tell Debian which display to use

Debian command 
export DISPLAY=:1

DISPLAY is an environment variable used by graphical Linux applications to know where to send their windows.

We are telling Debian to use display :1.

4.5 Test the connection

Debian command 
xdpyinfo >/dev/null && echo "X11 CONNECTION OK"

xdpyinfo asks the X11 server for display information.

>/dev/null hides the detailed output.

&& means the next command runs only if the first command succeeds.

echo prints our simple success message.

Expected output
X11 CONNECTION OK
If you see “X11 CONNECTION OK”, stop and celebrate this checkpoint. The Linux environment can communicate with the graphical display.

4.6 Start XFCE

Debian command 
dbus-launch --exit-with-session startxfce4

dbus-launch creates the DBus session used by the graphical desktop.

--exit-with-session ties the DBus session to the desktop session.

startxfce4 starts XFCE.

Desktop checkpoint

XFCE should now appear on the phone.

You should see a panel, desktop area, applications menu and other normal desktop components.

Chapter 05

Firefox: The First Real GUI Test

A desktop is much more convincing when it can actually run a real graphical application.

5.1 Why Firefox?

We could install many applications at this point, but Firefox provides a useful test.

If Firefox can open and display a website, several important parts of our graphical setup are working together:

  • XFCE
  • X11
  • Linux graphics
  • window management
  • input
  • network access

5.2 Install Firefox ESR

WHERE ARE WE?
Debian. You should see root@localhost:~#.
Debian command 
apt install firefox-esr -y

This installs the Firefox Extended Support Release package available to the Debian environment.

5.3 Launch Firefox

Debian command 
firefox-esr

This starts Firefox from the Debian environment.

What this proves:

If Firefox opens, the graphical Linux environment is doing real work rather than merely displaying an empty desktop.

Chapter 06

Understanding and Fixing Signal 9

This is one of the most important lessons in the entire setup: when Android kills a Linux process, understand the cause before applying the fix.

Process completed (signal 9)

6.1 What does signal 9 mean?

Signal 9 is a forceful process termination signal.

In this setup, Android's process management can be an important cause of the Linux desktop or one of its processes being killed.

Do not conclude that Debian is broken just because this message appears. The problem can be outside Debian itself.

6.2 Why ADB?

The setting we need to change is an Android system-level setting. Termux does not automatically have permission to change every Android system configuration.

Android Debug Bridge, or ADB, gives us a way to communicate with Android's debugging interface.

On a modern Android phone, Wireless Debugging can allow this communication without connecting a computer.

6.3 First make sure ADB itself works

ADB may produce its own problem before we even reach Wireless Debugging.

CANNOT LINK EXECUTABLE "adb": cannot locate symbol "_ZNSt6__ndk113__hash_memoryEPKvm"

If you see this, stop. Fix ADB first.

Termux command 
dpkg -S $(command -v adb)

command -v adb finds the ADB executable.

dpkg -S asks which installed Debian/Termux package owns that file.

We use this to confirm that the executable belongs to the android-tools package.

6.4 Reinstall Android Tools

Termux command 
pkg reinstall android-tools

This downloads and reinstalls the Android Tools package, including ADB.

6.5 Test ADB

Termux command 
adb version

We are asking ADB to report its version. If ADB responds normally, we can continue to Wireless Debugging.

6.6 Enable Wireless Debugging

Open:

Android Settings → Developer Options → Wireless Debugging

Turn Wireless Debugging on.

Never copy the IP address and port from another person's phone. Use the exact values displayed by your own phone.

6.7 Pair ADB

Termux command 
adb pair IP_ADDRESS:PAIRING_PORT

Replace the placeholders with the IP address and pairing port shown by your Android Wireless Debugging screen.

Android will ask for the pairing code shown on the phone.

6.8 Connect

Termux command 
adb connect IP_ADDRESS:PORT

This connects ADB to the device using the connection address displayed by Wireless Debugging.

6.9 Verify the connection

Termux command 
adb devices

This lists devices currently connected to ADB.

6.10 If pairing reports a protocol fault

protocol fault (couldn't read status message): Success

This does not automatically mean the phone is damaged.

Check that:

  • Wireless Debugging is still enabled.
  • You are using the current pairing information.
  • The pairing port is correct.
  • You have not accidentally used the connection port as the pairing port.

Retry the pairing process, then use adb devices after connecting.

6.11 Change the phantom-process setting

Once ADB is connected, run the following commands one at a time.

ADB command 
adb shell "/system/bin/device_config set_sync_disabled_for_tests persistent"

This sets the DeviceConfig synchronization mode needed for the configuration change that follows.

ADB command 
adb shell "/system/bin/device_config put activity_manager max_phantom_processes 2147483647"

This changes the Activity Manager's phantom-process limit to a very high value.

6.12 Verify the setting

ADB command 
adb shell "/system/bin/device_config get activity_manager max_phantom_processes"

This reads the setting back from Android.

Expected verification
2147483647
The important lesson: We did not treat the fix as magic. We identified the problem, repaired ADB, established a connection, changed the Android configuration and then verified the result.
Chapter 07

Audio, LibreOffice and Python

A desktop becomes much more useful when it can play sound, handle documents and run programming tools.

7.1 Install PulseAudio in Termux

WHERE ARE WE?
For the following command, return to Termux.
Termux command 
pkg install pulseaudio -y

This installs the PulseAudio server in Termux.

7.2 Adjust the PulseAudio configuration

Termux command 
sed -i 's/module-sles-sink/module-aaudio-sink/g' $PREFIX/etc/pulse/default.pa

sed edits text files from the command line. Here it changes the configured audio sink module.

7.3 Start PulseAudio

Termux command 
pulseaudio --start --load="module-native-protocol-tcp auth-ip-acl=127.0.0.1 auth-anonymous=1" --exit-idle-time=-1

7.4 Load the network protocol

Termux command 
pactl load-module module-native-protocol-tcp auth-ip-acl=127.0.0.1 auth-anonymous=1

A returned number such as 18 is a module identifier, not automatically an error.

7.5 Check the audio server

Termux command 
pactl info | grep -E "Server Name|Default Sink"
Example working output
Server Name: pulseaudio
Default Sink: AAudio_sink

7.6 Tell Debian where the audio server is

Return to Debian.
Debian command 
export PULSE_SERVER=127.0.0.1

127.0.0.1 means the local device. We are telling Debian applications to use the PulseAudio server running on the same phone.

7.7 LibreOffice

Debian command 
apt update
Debian command 
apt install libreoffice -y
Debian command 
libreoffice --version

This verifies that LibreOffice is installed and executable.

7.8 Python

Debian command 
python3 --version
Debian command 
python3

The prompt should change to: 

>>>
Python command 
print("Hello, Polycarp!")
Expected output
Hello, Polycarp!
Python command 
exit()

This leaves the Python interpreter and returns to the Debian shell.

Chapter 08

Python Data Tools and Thonny

8.1 The pip3 problem

One of the most useful lessons in a multi-environment setup is learning to check which Python installation a command is using.

Debian command 
pip3 --version

If this points to a Python installation under the Termux filesystem rather than Debian, do not use it for our Debian data environment.

Instead, explicitly ask Debian's Python interpreter to run pip.

Debian command 
python3 -m pip --version

The important part is python3 -m pip. It ties pip to the Python interpreter we explicitly selected.

8.2 Install virtual-environment support

Debian command 
apt install python3-venv -y

8.3 Create a data environment

Debian command 
python3 -m venv ~/data

This creates a Python virtual environment named data in your home directory.

8.4 Activate the environment

Debian command 
source ~/data/bin/activate
Prompt change
(data) root@localhost:~#

The (data) tells us the virtual environment is active.

8.5 Install NumPy, pandas and Matplotlib

Python environment command 
python3 -m pip install numpy pandas matplotlib

NumPy provides numerical computing tools.

pandas provides tools for structured and tabular data.

Matplotlib provides plotting and visualization.

8.6 Install Thonny

Debian command 
apt install thonny -y
Debian command 
thonny
Thonny interpreter

If Thonny asks which Python interpreter to use, select Local Python 3 and use /usr/bin/python3 when that option is available.

Chapter 09

Startup Automation with Termux:Widget

Once the desktop works, we should stop repeating the same long sequence of commands manually.

9.1 The idea

We will create one shell script.

The script will:

  • hold a wake lock,
  • start X11 when needed,
  • start PulseAudio,
  • load the audio connection,
  • enter Debian,
  • set the display,
  • set the audio server,
  • start XFCE.

9.2 Create the script

In Termux, create: 

~/start-linux.sh

9.3 Understand the first line

Script line 
#!/data/data/com.termux/files/usr/bin/bash

This tells Android/Termux which shell should interpret the script.

9.4 Keep the session awake

Script line 
termux-wake-lock

9.5 Start X11 only when needed

Script block 
if [ ! -S "$TMPDIR/.X11-unix/X1" ] && [ ! -S "/tmp/.X11-unix/X1" ]; then
Script line 
    termux-x11 :1 &
Script line 
    sleep 3

The script waits three seconds to give X11 time to start.

Script line 
fi

9.6 Start PulseAudio

Script line 
pulseaudio --start --load="module-native-protocol-tcp auth-ip-acl=127.0.0.1 auth-anonymous=1" --exit-idle-time=-1

9.7 Load the PulseAudio connection

Script line 
pactl load-module module-native-protocol-tcp auth-ip-acl=127.0.0.1 auth-anonymous=1 2>/dev/null

2>/dev/null redirects standard error output away. This keeps harmless repeated-module messages from cluttering the startup process.

9.8 Start Debian and XFCE

Script line 
proot-distro login debian --shared-tmp -- bash -c 'export DISPLAY=:1; export PULSE_SERVER=127.0.0.1; dbus-launch --exit-with-session startxfce4' &

proot-distro login debian enters Debian.

--shared-tmp keeps the temporary directory shared.

bash -c tells Debian to execute the quoted command.

DISPLAY=:1 selects the X11 display.

PULSE_SERVER=127.0.0.1 selects the local audio server.

startxfce4 starts the desktop.

9.9 Make the script executable

Termux command 
chmod +x ~/start-linux.sh

chmod +x gives the file executable permission.

9.10 Check the permissions

Termux command 
ls -l ~/start-linux.sh

9.11 Test before automating

Termux command 
~/start-linux.sh

Do not create the widget until the script works.

If the script itself fails, adding Termux:Widget will not fix it. First make the script work manually.

9.12 Install Termux:Widget

Official source: Termux:Widget on F-Droid

9.13 Create the shortcuts directory

Termux command 
mkdir -p ~/.shortcuts

9.14 Copy the startup script

Termux command 
cp ~/start-linux.sh ~/.shortcuts/"Start Linux"

9.15 Make the shortcut executable

Termux command 
chmod +x ~/.shortcuts/"Start Linux"

Add the Termux:Widget to the Android home screen. You should now have a shortcut named Start Linux.

Chapter 10

Ubuntu, Storage, Camera and Real-World Limits

10.1 Ubuntu is optional

Debian is our main tested environment in this tutorial. Ubuntu can be installed separately if it is available in the current PRoot-Distro list.

Termux command 
proot-distro list

If Ubuntu is listed:

Termux command 
proot-distro install ubuntu
Termux command 
proot-distro login ubuntu
Remember: Ubuntu and Debian are separate environments. Installing Ubuntu does not turn your Debian environment into Ubuntu.

10.2 Access Android shared storage

Return to Termux before running this command.

Termux command 
termux-setup-storage

Android will ask for storage permission. Accept it if you want Termux to access Android shared storage.

Android's shared storage and the Linux filesystem are different. Termux creates convenient links so that applications can work with shared Android files.

10.3 Camera access

Termux:API provides commands that communicate with Android APIs.

Official source: Termux:API on F-Droid

Termux command 
command -v termux-camera-photo

This checks whether Termux can find the camera command.

Android camera ≠ Linux webcam

Having access to termux-camera-photo does not automatically create a Linux webcam device such as /dev/video0.

Taking a photograph through Android's camera API and providing a webcam stream to a Linux browser are different technical tasks.

10.4 What this setup can realistically replace

This setup can make a phone useful for many tasks that normally benefit from a desktop environment:

  • web browsing
  • basic office work
  • spreadsheet work
  • Python programming
  • data analysis
  • terminal-based development
  • Linux experimentation
  • lightweight desktop applications

10.5 What it does not magically solve

  • Every desktop application will not run.
  • Some Linux applications require additional configuration.
  • Android hardware is not automatically exposed as normal Linux hardware.
  • Touch input is not identical to mouse and keyboard input.
  • Performance depends on the phone's CPU, GPU, RAM and thermal limits.
  • PRoot is not the same thing as a normal Linux installation.

Final checkpoint

  • Android remains underneath the setup.
  • Termux provides the base environment.
  • Debian provides the Linux userspace.
  • XFCE provides the desktop.
  • Termux:X11 displays the desktop.
  • ADB can help solve Android-level process-management problems.
  • Audio, office software and Python can extend the setup.
  • Automation can make the system easier to start.

What if the computer you need is already in your pocket?

This book takes you from a normal Android phone to a working Linux desktop environment, one carefully explained step at a time.

You will learn how Termux, PRoot-Distro, Debian, XFCE and Termux:X11 fit together; how to run graphical Linux applications; how to diagnose the infamous signal 9 problem; how to use ADB and Wireless Debugging; and how to add audio, LibreOffice, Python, data-analysis tools and startup automation.
